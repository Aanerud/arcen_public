Version 1.0, effective 2026-11-12

This document contains two agreements with the same substance:

- **Part A — Individual Contributor License Agreement**, for a person
  contributing on their own behalf;
- **Part B — Entity Contributor License Agreement**, for a company or other
  organisation (for example a studio) that authorises named people to
  contribute on its behalf.

Both are licence grants. **Neither is a copyright assignment**: you keep the
copyright in your contribution. They are modelled on the Apache Software
Foundation's Individual and Corporate Contributor License Agreements.

A plain-language explanation is in [CONTRIBUTING.md](CONTRIBUTING.md#the-contributor-license-agreement).
That explanation is not part of the agreement.

## How to accept

You accept this agreement with a statement in a pull request. A maintainer
records the statement and confirms on the pull request when it has been
recorded; a pull request is not merged before that. There is no separate
signing service.

- **Individuals (Part A):** put this statement, with the two fields filled
  in and otherwise unchanged, in the description of your first pull request,
  opened from your own GitHub account:

  > I have read the Arcen Contributor License Agreement, version 1.0 (CLA.md), and I agree to Part A for this and all my future contributions to Arcen.
  >
  > Name to be credited: [full name or handle]
  >
  > GitHub account: @[account]

- **Entities (Part B):** a person authorised to bind the Entity puts this
  statement, with the fields filled in and otherwise unchanged, in the
  description of a pull request (the Entity's first, or one opened for the
  purpose), from their own GitHub account:

  > On behalf of [Entity legal name], organisation number [number], [country], I accept Part B of the Arcen Contributor License Agreement, version 1.0 (CLA.md), and confirm that I am authorised to do so.
  >
  > Name and title: [name], [title]
  >
  > GitHub account: @[account]
  >
  > Designated Contributors (Schedule B-1): [name or handle] — @[GitHub account], one per line

The statement is public, as the pull request is. Give no more personal data
than the fields ask for; a handle is enough where a name is not wanted.
